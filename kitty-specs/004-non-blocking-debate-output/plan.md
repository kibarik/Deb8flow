# Implementation Plan: Non-Blocking Debate Output Recording

**Branch**: `004-non-blocking-debate-output` | **Date**: 2025-02-14 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/kitty-specs/004-non-blocking-debate-output/spec.md`

## Summary

Add file output recording capability to the document debate CLI with non-blocking, fault-tolerant async writes. The feature adds a `--output` CLI argument that writes each debate message to a plain text file in real-time using Python's asyncio + aiofiles pattern, ensuring write failures never impact the main debate flow.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: langgraph==0.3.21, rich==14.0.0, **aiofiles** (new dependency for async file I/O)
**Storage**: Plain text files (transcript output)
**Testing**: pytest==8.3.5
**Target Platform**: CLI tool (Linux/macOS/Windows)
**Project Type**: Single project (Python async CLI application)
**Performance Goals**: File writes must not add >5% overhead to debate execution time; writes complete within 1 second of message generation
**Constraints**: Must not block main debate workflow; must handle write failures gracefully; output only for CLI (not programmatic API)
**Scale/Scope**: Single-debate output to one file; no concurrent write support needed

## Phase 0: Research & Technical Decisions

### Research Tasks

1. **Async File I/O Best Practices**
   - Research: async file writing patterns in Python 3.11+
   - Evaluate: aiofiles vs custom thread pool implementation
   - Decision: Use aiofiles for native async file I/O (chosen by user)

2. **Error Handling for Non-Blocking Writes**
   - Research: Best practices for handling async write failures without propagating exceptions
   - Evaluate: Logging strategies, retry policies, graceful degradation
   - Decision: Log error with traceback, continue debate, no retries (keep simple)

3. **Message Format Standards**
   - Research: Plain text transcript formats for debate/dialogue systems
   - Evaluate: Speaker labels, timestamp formats (ISO 8601 vs human-readable)
   - Decision: Speaker label in brackets, ISO 8601 timestamp, plain text content

### Research Findings

**Decision 1: Async File I/O Approach**
- **Chosen**: `aiofiles` library with asyncio
- **Rationale**: Native async file operations, integrates seamlessly with existing async workflow, minimal code changes
- **Alternatives Considered**: Threading.Thread (adds complexity), ThreadPoolExecutor (overhead for single file)

**Decision 2: Error Handling Strategy**
- **Chosen**: Try-except with logging only, never re-raise
- **Rationale**: User explicitly requested that write failures must not impact main flow; logging provides visibility without interrupting debate
- **Alternatives Considered**: Retry with backoff (could delay main flow), Circuit breaker (over-engineering for single file)

**Decision 3: Message Format**
- **Chosen**: `[PRO] 2025-02-14T12:00:00Z\n<message content>\n\n`
- **Rationale**: Human-readable, machine-parseable, matches transcript conventions
- **Alternatives Considered**: Markdown (requires formatting), JSON (not plain text)

## Phase 1: Design & Contracts

### Data Model (data-model.md)

**DebateMessage Entity**
- Fields:
  - `speaker`: Enum["PRO", "CON", "JUDGE", "MODERATOR"] - Message source
  - `timestamp`: ISO 8601 datetime string - When message was generated
  - `content`: str - The actual message text
- Validation: Content is non-empty string, timestamp is valid ISO format
- Relationships: None (value object)

**AsyncFileWriter Entity**
- Fields:
  - `file_path`: str - Target output file path
  - `enabled`: bool - Whether writing is active (false if init failed)
  - `write_queue`: asyncio.Queue - Queue for pending writes
- Methods:
  - `write_message(message: DebateMessage) -> None` - Queue a message for async write
  - `_writer_task() -> Coroutine` - Background task that processes queue
  - `close() -> None` - Flush and stop writer

**TranscriptFormatter Entity**
- Methods:
  - `format_message(message: DebateMessage) -> str` - Convert to plain text format
  - `validate_path(path: str) -> bool` - Check if path is writable

### API Contracts

### Developer Quickstart (quickstart.md)

**Adding Output Recording to a New CLI**

To add output recording to a new CLI tool:

1. Import the `AsyncFileWriter`:
   ```python
   from src.output.async_file_writer import AsyncFileWriter
   from src.output.transcript_formatter import TranscriptFormatter
   ```

2. Create writer in your async main function:
   ```python
   writer = AsyncFileWriter(args.output) if args.output else None
   ```

3. Pass writer to your workflow/nodes:
   ```python
   result = await workflow.run(initial_state, output_writer=writer)
   ```

4. Write messages from your nodes:
   ```python
   if output_writer:
       message = DebateMessage(speaker="PRO", timestamp=..., content="...")
       await output_writer.write_message(message)
   ```

5. Cleanup on completion:
   ```python
   if writer:
       await writer.close()
   ```
