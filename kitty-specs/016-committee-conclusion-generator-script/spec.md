# Committee Conclusion Generator Script

## Feature Description

A standalone CLI script that regenerates the `conclusion.md` file for existing Product Committee runs by analyzing the `final_report.md` content using AI. This allows users to regenerate or update conclusions without re-running the entire committee process.

## User Scenarios & Testing

### Primary Scenario: Regenerate Conclusion from Existing Report

1. User has an existing committee run directory (e.g., `committee_output/RUN_20260217_230136_----100/`)
2. User runs: `python3 conclusion_results.py '/path/to/final_report.md'`
3. Script reads the `final_report.md` file
4. Script uses AI to analyze the full report content
5. Script generates a new `conclusion.md` file in the same directory as the input file
6. Original `final_report.md` remains unchanged

### Edge Cases

- **Invalid input path**: Script exits with clear error message
- **Missing final_report.md**: Script exits with file not found error
- **Empty final_report.md**: Script handles gracefully, reports empty content
- **All debate rooms failed**: Conclusion includes error analysis and troubleshooting steps
- **Mixed success/failure**: Conclusion reflects partial results accurately
- **Malformed markdown**: Script attempts to parse what it can, reports parsing issues

## Functional Requirements

### FR-01: Command-Line Interface
- The script MUST accept a single positional argument: path to `final_report.md`
- The script MUST validate the input path exists and is readable
- The script MUST exit with a non-zero status code if validation fails
- The script MUST provide clear error messages for validation failures

### FR-02: Report Parsing
- The script MUST read the `final_report.md` file from the provided path
- The script MUST extract the committee question from the report
- The script MUST extract room-by-room results from the report
- The script MUST identify successful rooms, failed rooms, and skipped rooms
- The script MUST extract error messages for failed rooms

### FR-03: AI-Powered Conclusion Generation
- The script MUST use AI to analyze the full committee report content
- The script MUST generate a conclusion that includes:
  - Committee question
  - Executive summary with room success/failure counts
  - Overall verdict (if successful rooms exist)
  - Room results summary with winners and key takeaways
  - Error analysis (if rooms failed)
  - Next steps/recommendations
- The script MUST handle the case where all rooms failed with appropriate troubleshooting guidance

### FR-04: Output Generation
- The script MUST write the generated conclusion to `conclusion.md` in the same directory as the input `final_report.md`
- The script MUST overwrite any existing `conclusion.md` file
- The output MUST be in markdown format
- The output MUST include the generation timestamp

### FR-05: Error Handling
- The script MUST handle file I/O errors gracefully
- The script MUST handle AI API errors with informative messages
- The script MUST handle malformed markdown input
- The script MUST log errors to stderr for debugging

### FR-06: Configuration
- The script MUST support the same LLM configuration as the main project (OpenAI, Azure, etc.)
- The script MUST read configuration from environment variables (e.g., `OPENAI_API_KEY`)
- The script MUST respect the `.env` file if present

## Success Criteria

1. **Regeneration Success**: Users can successfully regenerate `conclusion.md` for any existing committee run
2. **Time Efficiency**: Conclusion generation completes within 30 seconds for typical reports
3. **Output Quality**: Generated conclusions include all required sections (executive summary, room results, error analysis)
4. **Error Handling**: All error conditions (missing files, API failures) produce clear, actionable error messages

## Key Entities

- **final_report.md**: Input file containing the full committee report with room results, errors, and metadata
- **conclusion.md**: Output file containing the AI-generated summary and analysis
- **Committee Run**: A single execution of the Product Committee Orchestrator with a unique run ID
- **Debate Room**: One of four committee rooms (TPM_vs_CPO, TPM_vs_CFO, TPM_vs_CTO, TPM_vs_BDM)
- **AI Service**: LLM API (OpenAI, Azure, or configured alternative) used for conclusion generation

## Dependencies

- **Existing Committee Run**: A `final_report.md` file must exist in a committee output directory
- **LLM API Access**: Valid API credentials must be configured (via environment variables)
- **Deb8flow Codebase**: The script shares configuration with the main project (LLM configs, etc.)

## Assumptions

1. The `final_report.md` follows the format generated by `product_committee.py`
2. The user has valid API credentials configured in their environment
3. The script runs from the Deb8flow project root directory
4. The AI model used is the same as configured for the main project (default: OpenAI)
5. The conclusion format follows the existing `generate_conclusion()` function structure
