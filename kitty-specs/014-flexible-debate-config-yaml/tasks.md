# Work Packages: Flexible Debate Configuration with YAML

**Inputs**: Design documents from `/kitty-specs/014-flexible-debate-config-yaml/`
**Prerequisites**: plan.md, spec.md, data-model.md, contracts/schema.md, research.md

**Tests**: This feature includes test coverage for configuration loading, validation, and workflow integration as required by the constitution (pytest required).

**Organization**: Fine-grained subtasks (`Txxx`) roll up into work packages (`WPxx`). Each work package must be independently deliverable and testable.

**Prompt Files**: Each work package references a matching prompt file in `/tasks/` generated by `/spec-kitty.tasks`. Treat this file as the high-level checklist; keep deep implementation detail inside the prompt files.

## Subtask Format: `[Txxx] [P?] Description`
- **[P]** indicates the subtask can proceed in parallel (different files/components).
- Include precise file paths or modules.

## Path Conventions
- Project root: `/` (repository root)
- Configuration module: `configurations/`
- Node modules: `nodes/`
- Workflow modules: `workflow/`
- CLI scripts: `main.py`, `document_debate_cli.py`
- Tests: `tests/test_config/`, `tests/test_workflow/`
- Examples: `examples/`

## Work Package WP01: Configuration Data Model (Priority: P0)

**Goal**: Create the core configuration data structures and loader using Python standard library YAML parsing.

**Independent Test**: Configuration dataclasses are defined; YAML loader can parse a valid config file; validation catches common errors.

**Prompt**: `/tasks/WP01-config-data-model.md`

**Estimated Prompt Size**: ~350 lines

### Included Subtasks
- [ ] T001 Create DebateConfig, WorkflowConfig, RoleConfig, TriggerConfig, ModelConfig, and FactCheckingConfig dataclasses in `configurations/debate_config.py`
- [ ] T002 [P] Implement YAML configuration loader using `yaml.safe_load()` in `configurations/debate_config.py`
- [ ] T003 [P] Implement configuration validation function with clear error messages in `configurations/debate_config.py`
- [ ] T004 [P] Implement prompt resolution logic (inline vs file, precedence rules) in `configurations/debate_config.py`
- [ ] T005 [P] Add configuration error classes (ConfigNotFoundError, ValidationError, PromptFileNotFoundError, ModelNotFoundError) in `configurations/debate_config.py`
- [ ] T006 Create configuration module `__init__.py` with public API exports

### Implementation Notes
- Use `dataclasses` for type safety and clarity
- Use `yaml.safe_load()` to prevent code injection
- Validation should check: required fields, data types, value ranges, model references, role uniqueness
- Prompt resolution: paths relative to config file directory, `prompt_file` takes precedence over inline `prompt`
- Error messages must include field name and expected format

### Parallel Opportunities
- T002-T005 can be developed in parallel once T001 dataclass structure is defined

### Dependencies
- None (foundation package)

### Risks & Mitigations
- **Risk**: YAML parsing errors may be cryptic
- **Mitigation**: Add custom error handling with clear messages indicating file path and line number
